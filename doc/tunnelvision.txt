1. Introduction                                          *tunnelvision-introduction*

TunnelVision dims unrelated lines and keeps attention on the targeted symbol.

Modes >
  static   Track the symbol selected on activation.
  dynamic  Retarget as the cursor moves.
  flow     Expand a successful source path through assignment relationships.
<

Scope controls where matching is searched >
  function  Use nearest function-like scope when Tree-sitter is available.
  buffer    Use full buffer.
<

Source chains describe how matching lines are found. The default is LSP first,
then Tree-sitter, then word fallback:
>
  sources = { "lsp", "treesitter", "word" }
<

2. Installation                                           *tunnelvision-install*

lazy.nvim >lua
  {
    "leolaurindo/tunnelvision.nvim",
    opts = {},
  }

mini.deps >lua
  MiniDeps.add({ source = "leolaurindo/tunnelvision.nvim" })
  require("tunnelvision").setup()
<

packer.nvim >lua
  use({
    "leolaurindo/tunnelvision.nvim",
    config = function()
      require("tunnelvision").setup()
    end,
  })
<

Requirements >
  - Neovim 0.9+
  - Optional: Tree-sitter for scope detection and the treesitter source
  - Optional: LSP with documentHighlight support
<

3. Quick start                                          *tunnelvision-quickstart*

Call `require("tunnelvision").setup()` first so `:TunnelVision` is available.

  :TunnelVision on
  :TunnelVision add
  :TunnelVision next
  :TunnelVision prev
  :TunnelVision next-track
  :TunnelVision prev-track
  :TunnelVision off

Use |:TunnelVision| with subcommands. `on` focuses one symbol and replaces
existing tracks; `add` keeps them. `mode`, `direction`, `scope`, and `source`
show their persistent defaults when called without an argument. Use
`:TunnelVision status` to inspect the active buffer configuration.

4. Commands                                               *tunnelvision-commands*
                                                        *:TunnelVision*

  :TunnelVision on
      Replace all tracks with the symbol under cursor (the original behavior).

  :TunnelVision add
      Add the symbol under cursor without removing other tracks.

  :TunnelVision pin
      Add a fixed track even with a dynamic mode. One-shot highlights apply.

  :TunnelVision remove
      Remove the track under cursor, or the most recently added track.

  :TunnelVision retarget
      Compatibility alias for :TunnelVision on.

  :TunnelVision off
      Clear all tracks in the current buffer.

  :TunnelVision toggle
      Toggle TunnelVision on or off.

  :TunnelVision dim {#RRGGBB|group|none}
      Override the dim style in the current buffer. A hex value sets the
      foreground; a highlight group copies its attributes. `none` disables
      dimming even if a track requests it.

  :TunnelVision dim reset
      Clear the buffer dim override and force-dim setting, returning to the
      setup style. Without an argument, `dim` reports the current override.

  :TunnelVision next
      Jump to the next occurrence or unmatched path line across all tracks.

  :TunnelVision prev
      Jump to the previous occurrence or unmatched path line across all tracks.

  :TunnelVision next-track
      Jump to the next occurrence or unmatched path line in the track under the cursor.
      If tracks overlap, use the latest-added track. Away from a tracked occurrence
      or path line, use the latest track.

  :TunnelVision prev-track
      Jump to the previous occurrence or unmatched path line in the selected track.
      If tracks overlap, use the latest-added track. Away from a tracked occurrence
      or path line, use the latest track.

  :TunnelVision refresh
      Recompute all active tracks with their saved options.

  :TunnelVision status
      Show active-buffer state, mode, source chain, and tracked symbols.

  :TunnelVision mode [static|flow|dynamic|dynamic_flow]
      Query or set the mode default for new tracks. Existing tracks are unchanged.

  :TunnelVision direction [forward|backward|both]
      Query or set the persistent flow-direction default.
      Direction is used in flow and dynamic_flow modes.

  :TunnelVision scope [function|buffer]
      Query or set the persistent search-scope default.

  :TunnelVision source [value]
      Query or set the persistent source-chain default.

      Supported command values include:
        word
        lsp
        treesitter
        lsp,word
        treesitter,word
        lsp,treesitter,word

      Deprecated legacy values remain supported:
        lsp_else_word
        lsp_and_word

      Comma syntax means fallback order. Strict `combine(...)` source steps are
      Lua-only.

5. Configuration                                            *tunnelvision-config*

Default shape >lua
  require("tunnelvision").setup({
    mode = "static",
    scope = "function",
    sources = { "lsp", "treesitter", "word" },
    flow_settings = {
      direction = "forward",
      extra_keywords = {},
      analyzers = { "treesitter", "text" },
    },
    fallback_warn = "once",
    lsp_timeout_ms = 150,
    highlights = { line = true },
    dim = nil,
    max_dim_lines = 6000,
    notify = true,
  })
<

Options >
  mode                          static | flow | dynamic | dynamic_flow
  scope                         function | buffer
  sources                       ordered source fallback chain
  flow_settings.direction       forward | backward | both
  flow_settings.extra_keywords  extra identifiers ignored in flow analysis
  flow_settings.analyzers       ordered treesitter | text fallback chain
  flow_settings.max_depth       positive hop limit capped at 32; nil uses 32
  fallback_warn                 LSP fallback and structural: once | always | never
  lsp_timeout_ms                timeout for async LSP documentHighlight requests
  highlights                    visual contexts and positive styles
  dim                           nil, "none", highlight group, #RRGGBB, or table
  max_dim_lines                 skip dimming in very large buffers
  notify                        enable plugin notifications
<

By default, `dim = nil` derives TunnelVision's dim style from your colorscheme's
`Comment` highlight. Use `dim = "Comment"` only when you want to explicitly copy
that highlight group. `dim = "none"` disables dimming but retains positive
highlight styles.

`fallback_warn` controls legacy LSP-to-word and structural warnings. Strict LSP
mode warns once per buffer when unavailable regardless of this setting. All
notifications, including command queries and status output, respect `notify`.

Flow analyzers are separate from sources. Sources choose the initial matching
path; flow analyzers expand assignments from the active symbol. The default
`{ "treesitter", "text" }` chain uses best-effort Tree-sitter analysis and
silently falls back to text. Use a one-item list for strict behavior.

`forward` follows dependencies to dependents, `backward` follows inputs feeding
the selected symbol, and `both` follows both directions. `status()` exposes the
analyzer used, fallback state, tracked identifier count, and flow-added lines.

Dim examples >lua
  require("tunnelvision").setup({ dim = nil })
  require("tunnelvision").setup({ dim = "Comment" })
  require("tunnelvision").setup({ dim = "#565f89" })
  require("tunnelvision").setup({ dim = { fg = "#565f89", italic = true } })
  require("tunnelvision").setup({ dim = "none" })
<

The setup style is the default for every buffer. `set_buffer_dim(style, bufnr?)`
sets a buffer-local override (same style forms as `setup({ dim = ... })`);
`set_buffer_dim(nil, bufnr?)` clears it and force-dim, returning to setup's style.
`:TunnelVision dim reset` does the same for the current buffer.
`force_buffer_dim(true, bufnr?)` enables dimming even if all active tracks
opt out; pass `false` to stop forcing it. Both return a boolean and default to
the current buffer. Neither a style override nor force creates visible dimming
without active tracks; an effective style of `"none"` prevents dimming even
when forced. A buffer override may replace a setup style of `"none"`. Settings
survive `off()` and are cleared on buffer deletion. `setup()` changes dim style
for active buffers without reconfiguring their tracks.

6. Lua API                                                    *tunnelvision-api*

From `require("tunnelvision")` >
  setup(opts?)
  on(opts?)
  add(opts?)
  pin(opts?)
  on_many(positions, opts?)
  set_buffer_dim(style?, bufnr?)
  force_buffer_dim(enabled, bufnr?)
  remove()
  retarget(opts?)
  off()
  toggle()
  next(count?) / prev(count?)
  next_track(count?) / prev_track(count?)
  refresh()
  is_active(bufnr?)
  status(bufnr?)
  combine(...)
  register_source(name, handler)
  get_sources() / set_sources(sources)
  get_mode() / set_mode(mode)
  get_direction() / set_direction(direction)
  get_scope() / set_scope(scope)
  add_keywords(words)
  get_source() / set_source(source)
<

`on(opts)` replaces every track in the buffer with the symbol under the cursor.
`add(opts)` keeps existing tracks and adds one. `pin(opts)` adds a fixed track
even when the requested mode is `dynamic` or `dynamic_flow`, converting it to
`static` or `flow`. All three accept one-shot overrides such as `scope`,
`sources`, `mode`, `flow_settings`, and `highlights`; a supplied non-empty
`highlights` table replaces setup highlight rules for that activation. Setting
`dim = "none"` opts that activation out of requesting dimming; omitted `dim`
requests it. One-shot dim colors, `dim_hl`, and `max_dim_lines` are rejected.
Each track styles its own ranges; newer tracks override conflicting style
attributes. The focused union shares one buffer-wide dim layer. `next`/`prev`
navigate the union of all track occurrences. `retarget(opts?)` is retained as a
compatibility alias for `on(opts?)`.
`next_track`/`prev_track` select the track at the cursor (the most recently added
match if tracks overlap), falling back to the latest track when the cursor is
outside tracked occurrences and path lines. `dynamic_flow` moves and recomputes
flow; `pin({ mode = "flow" })` and `pin({ mode = "dynamic_flow" })` create
pinned flow tracks.
`on_many(positions, opts)` accepts (1,0)-indexed current-buffer positions;
with dynamic mode, all but the last position are pinned. Neovim 0.13's
cursor-enumeration behavior must be verified before native multicursor
activation or cursor creation is wired up.

Example >lua
  local tv = require("tunnelvision")
  tv.on({ scope = "buffer", sources = { "word" } })
<

`get_source()` and `set_source(source)` are compatibility APIs for old source
strings. Prefer `get_sources()` and `set_sources(sources)` for new code.

7. Sources                                                *tunnelvision-sources*

Source chains are simple and composable. Each step is tried in order. The first
step that produces usable lines wins.

Fallback chain >lua
  require("tunnelvision").setup({
    sources = { "lsp", "treesitter", "word" },
  })
<

Source engines >
  lsp         Semantic and async when documentHighlight is supported.
  treesitter  Syntax-aware, parser-based, and not semantic.
  word        Textual, broad, language-agnostic fallback with lightweight masking.
<

`combine(...)` creates one strict combined source step. It behaves like "all":
every source inside the step must produce usable matches. If all members succeed,
their line sets are merged. If any member fails or returns no matches, the whole
step fails and the chain continues.

Strict combined source step >lua
  local tv = require("tunnelvision")

  tv.setup({
    sources = {
      tv.combine("lsp", "treesitter"),
      "word",
    },
  })
<

Custom sources                                      *tunnelvision-custom-sources*

`register_source(name, handler)` adds a synchronous Lua source. Register it
before using its name in `sources`. The `assertions` source below is user-defined
by this example; it is not built in.

Custom source example >lua
  local tv = require("tunnelvision")

  tv.register_source("assertions", function(ctx)
    local matches = {}
    local lines = vim.api.nvim_buf_get_lines(
      ctx.bufnr,
      ctx.scope.start_line - 1,
      ctx.scope.end_line,
      false
    )

    for offset, text in ipairs(lines) do
      local symbol = "%f[%w_]" .. vim.pesc(ctx.symbol) .. "%f[^%w_]"
      if text:find("assert", 1, true) and text:find(symbol) then
        matches[ctx.scope.start_line + offset - 1] = true
      end
    end

    return matches
  end)

  tv.setup({ sources = { "lsp", "assertions", "word" } })
<

The handler context contains `bufnr`, `symbol`, `anchor`, `scope`, `mode`,
`direction`, and `keywords`. Return a line set such as `{ [3] = true }`.
Returning `nil`, `false`, an empty table, or raising an error continues to the
next source. Invalid and out-of-scope line numbers are ignored.

Custom sources work in `combine(...)`. They are synchronous and Lua-only, so
`:TunnelVision source` does not accept their names. Built-in and legacy source
names cannot be replaced.

Tree-sitter limitations >
  - More precise than word matching for syntax, less semantic than LSP.
  - Does not fully resolve shadowing.
  - Does not resolve imports, aliases, type inference, or external identity.
  - Depends on installed parser quality and grammar node names.
<

Word matching masks common single-line quoted strings and `//`, `#`, and `--`
comment suffixes. It is intentionally lightweight and does not parse every
language's string or comment syntax.

8. Visual focus                              *tunnelvision-visual-focus*

`highlights` selects visual contexts and optionally adds positive highlight
attributes. Omitted or empty, it defaults to `{ line = true }`. A non-empty
table replaces that default rather than merging with it. In `on(opts)`, omitting
`highlights` inherits setup rules; an empty table selects the line default, and
a non-empty table replaces them for that activation.

Rule values >
  missing or false  disable the context
  true or {}        enable it while preserving original syntax colors
  style table       enable it and apply the specified attributes
<

Contexts >
  scope_head  First line of enclosing function, conditional, loop, and clause
              heads found by Tree-sitter.
  statement   Nearest recognized declaration or statement around each path
              occurrence, limited to 50 lines and clipped to the active scope.
  line        Complete source/flow path lines.
  symbol      Exact source-owned and flow-relevant symbol ranges. With only this
              context enabled, the rest of each matched line is dimmed (when dimming active).
<

Overlapping contexts compose in this order:

  scope_head -> statement -> line -> symbol

Later contexts override only attributes they specify and inherit the rest.
Across tracks, newer tracks override only conflicting attributes. Unstyled
contexts still protect their ranges from the shared dim layer.
Supported style keys are `fg`, `bg`, `bold`, `italic`, `underline`, `undercurl`,
and `strikethrough`. `fg` and `bg` accept Neovim color strings or numbers; the
other standard keys are booleans. Numeric `bg_opacity` is clamped to 0 through 1
and pre-blends the context's `bg` against `Normal`. This is pseudo-opacity, not
true alpha blending. Without a usable `bg` or `Normal` background, the
configured background is used unchanged.

Examples >lua
  -- Default line focus
  {}

  -- Token-only focus, original colors
  { highlights = { symbol = true } }

  -- Statement focus with composed line and symbol emphasis
  {
    highlights = {
      statement = true,
      line = { bold = true },
      symbol = { italic = true, underline = true },
    },
  }

  -- Structural heads with custom styling
  {
    highlights = {
      line = true,
      scope_head = { bold = true },
    },
  }

  -- Positive styles without requesting dimming from this track
  {
    dim = "none",
    highlights = { symbol = { bold = true } },
  }
<

Symbol geometry belongs to the source that wins the chain. LSP uses returned
document-highlight ranges, Tree-sitter uses exact matching identifier nodes,
and `word` uses exact whole-word occurrences after lightweight masking. Custom
source lines derive active-symbol ranges where present. In flow mode, any
successful source can seed expansion, and ranges for all tracked, flow-relevant
identifiers are added on flow path lines.

`statement` and `scope_head` use Tree-sitter independently of `sources`. They do
not require the `treesitter` source, and LSP does not resolve them. Lookup starts
at exact symbol columns, or at the first nonblank column for a custom-source line
without a range. If structure is unavailable or unsafe, `statement` falls back
to path lines and `scope_head` is skipped. Warnings obey
`fallback_warn = "once" | "always" | "never"` (`once` is per buffer) and
`notify`.

Structural lines never become navigation targets. `next` and `prev` continue
through source/flow path lines only.

9. Migration                                            *tunnelvision-migration*

Deprecated APIs remain supported and do not emit runtime deprecation warnings in
this release. Prefer the new API for new configuration.

Old to new >
  source = "word"            -> sources = { "word" }
  source = "lsp"             -> sources = { "lsp" }
  source = "lsp_else_word"   -> sources = { "lsp", "word" }
  source = "lsp_and_word"    -> sources = { tv.combine("lsp", "word") }
  direction = "both"         -> flow_settings = { direction = "both" }
  extra_keywords = { ... }    -> flow_settings = { extra_keywords = { ... } }
  dim_hl = "..."             -> dim = ...
<

There is intentionally no `treesitter_else_word` value. Use explicit fallback
chains such as `sources = { "treesitter", "word" }`.

Version 0.4 adds opt-in visual rules and reorganizes rendering internals, but no
configuration migration is required. `setup()`, `setup({})`, legacy `source`
values, and modern `sources` chains behave as before without `highlights`: line
focus with Comment-derived dimming. In particular, `source = "lsp_else_word"`
maps to `sources = { "lsp", "word" }`.

Breaking change after 0.4: one-shot dim colors must move to
`set_buffer_dim(style)` or `setup({ dim = style })`; only `on({ dim = "none" })`
remains valid. One-shot `dim_hl` and `max_dim_lines` must move to `setup()`.

`on()` intentionally keeps its original replace-one-target behavior, so existing
mappings do not start accumulating tracks. Use `add()`, `pin()`, or `on_many()`
when multiple tracks are wanted; `:TunnelVision retarget` still behaves like
`:TunnelVision on`. The `dim`-related breaks above apply to the same release.

11. Troubleshooting                         *tunnelvision-troubleshooting*

- No symbol under cursor: move to a word identifier before `:TunnelVision on`.
- Slow or empty LSP mode: try `:TunnelVision source word` to compare.
- No LSP highlights: use `sources = { "lsp", "word" }` for word fallback.
- Too many word matches: try `sources = { "treesitter", "word" }`.
- Function scope behaving like buffer: check Tree-sitter health/status.
- Flow mode is heuristic, not full dataflow analysis.
